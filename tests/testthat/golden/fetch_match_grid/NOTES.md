# Goldens — fetch_match_grid (FMG), flow step 6

Generated by `R/sandbox/fetch_match_grid.R` from the **original**
`R/original/fetch_match_grid.R` (read-only). They record the original's
behaviour **faithfully, bugs included**. The refactor's intentional divergences
(below) are asserted as **derived** expectations in the testthat step — not
compared verbatim — mirroring the trio (ERC/FR/FTM) and fetch_soundscape_metadata.

**Fixture note:** the original `fetch_match_grid` does **not** read the WAVs — it
trusts the data.frame columns. Files only need to **exist** for the
`file.exists()` branches. The generator therefore builds small input frames from
**real committed paths** (template_trio legacy cuts + the audiomoth corpus) for
"present" rows and synthetic non-existent paths for "missing" rows, with crafted
metric columns to drive every compatibility filter deterministically.

## Faithfully-recorded ORIGINAL behaviour (what the goldens show)

- **G1:** all-compatible inputs → 4-row cartesian, "All files compatible" message,
  no warning. The refactor must reproduce this happy path.
- **G2:** the six filters run **sequentially, mutating `res`**, so the per-reason
  counts are conditional on the previous filters (missing-ss 4 → missing-tmpl 3 →
  sample_rate 3 → min_freq 2 → max_freq 3 → duration NA). The run also emits a
  **recycling warning** and ends with a **phantom all-NA row**.
- **G3:** a single `NA` in a compared column **aborts** the function.

## Intentional divergences the refactor WILL introduce (asserted, not matched)

| DEBT item | Original (golden) | Refactor (derived expectation) |
|---|---|---|
| **FMG-01** | `NA` in a compared column → **crash** (G3) | `NA` handled deterministically (routed to an "incomplete metadata" exclusion), no crash |
| **FMG-02** | `template_path = NA` (reference_metadata) would be dropped as "missing file" | branch on `template_mode`; reference_metadata validated via origin + sha256, not file.exists |

| **FMG-09** | stale `nyquist_frequency` → recycling warning, wrong max_freq count, **phantom all-NA row** (G2) | no recycling, no phantom rows; predicates evaluated on the current rows / unique values |
| **FMG-101** | n/a | optional DuckDB **VIEW** output (in-memory return stays default) |
| **FMG-102** | n/a | optional `verify_integrity` sha256 gate |
| **FMG-103** | n/a | channel compatibility carried/checked |

So G2's phantom-NA row and recycling warning, and G3's crash, are **negative
goldens**: the refactor is expected to *differ* from them, and the testthat step
asserts the corrected behaviour rather than byte-equality.
