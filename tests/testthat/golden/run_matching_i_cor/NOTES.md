### Key captured facts (`summary.csv`)

- **Localization is correct** in the original: cor peaks land **inside** the
  truth window (t075 0.821 @ 10.335 s; t092 0.991 @ 37.345 s — the window
  **center**, i.e. cor is center-indexed).
- `sliding_window` = template frame count (t075 172, t092 104); `sw_start =
  sw %/% 2`, `sw_end = sw - sw_start - 1`.
- `head_drop_triggered = FALSE`: `padded_pre_head == n_time` exactly, so the
  `head(score_vec, -1)` band-aid (RMC-02) never fires on these fixtures.
- `edge_left_val == edge_right_val == score_min` (the per-pair minimum used as
  border fill — RMC-03): t075 −0.1994, t092 −0.2364.
- No warnings / messages / errors on the happy path.

## Intentional divergences (refactor will CHANGE these — assert as DERIVED)

These are **expected** to differ in `R/refactored/`; the testthat step encodes
the *corrected* expectation, not the golden value.

- **RMC-01 — padding asymmetry.** The original fills borders with
  `rep(min, sw_start - 1)` left and `rep(min, sw_end + 1)` right (columns
  `left_fill = sw_start-1`, `right_fill = sw_end+1` in `summary.csv`). The natural
  geometry is `sw_start` / `sw_end`, so the original score series is shifted **one
  frame left** vs `time_vec`. Total length still sums to `n` (hence
  `head_drop = FALSE`), which hides the bug from length checks. The refactor uses
  `pad_left = sw_start`, `pad_right = sw_end` with
  `stopifnot(pad_left + n_windows + pad_right == n_time)` and asserts a
  known-peak-frame alignment → the refactored peak frame may differ by **one
  frame** from the golden. (Decision: accepted; propagate to RMD.)
- **RMC-02 — `head(score_vec, -1)` band-aid.** Removed in the refactor (replaced
  by `stopifnot(length(score_vec) == n_time)`). No observable effect on these
  fixtures (`head_drop = FALSE`) but asserted gone.
- **RMC-03 — `min`-fill / NA replacement.** The original fills borders and
  residual `NA`s with the **per-pair** `min(score_vec)` (captured as
  `edge_left_val`/`edge_right_val` == `score_min`). The refactor uses the
  principled sentinel **`0`** (no linear association for Pearson), uniform across
  versions → the border values change (golden edges = per-pair min; refactored
  edges = 0).

## Edge cases — ORIGINAL opaque behaviour captured (`edge_cases_conditions.csv`)

The refactor replaces each of these with a clear, file/column-named guard; the
testthat step asserts the **new** clear error, using these rows as the "before"
baseline (no verbatim-equality golden — the messages themselves change).

- **RMC-13 — soundscape shorter than the template window.** Truncating the
  source soundscape to ~1 s (far fewer frames than the 172-frame template) makes
  `slider::slide(..., .complete = TRUE)` return all `NULL` → empty `ind` →
  `1:length(ind)` = `c(1, 0)` → `ind[[1]]` on an empty list. Original error:
  **"subscript out of bounds"** (opaque). Refactor: explicit short-soundscape
  `stop()` with a descriptive message (use `seq_along`/`seq_len`).
- **RMC-14 — missing required `df_grid_i` column.** Dropping `template_wl` makes
  `spec_params$wl = NULL`. Original: a tibble warning *"Unknown or uninitialised
  column: `template_wl`."* then **"Error generating spectrograms: argument is of
  length zero"** (opaque). Refactor: validate `df_grid_i` at the dispatcher entry
  with a column-named message.
- **RMC-11 — `flim` above Nyquist.** Setting `template_max_freq = 30` kHz (>
  24 kHz Nyquist at 48 kHz) is unchecked; `seewave::spectro` fails with
  **"Error generating spectrograms: subscript out of bounds"** (opaque). Refactor:
  validate `flim` against each WAV's Nyquist and assert soundscape/template bin
  compatibility before building spectrograms.
