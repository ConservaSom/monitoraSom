# Goldens — `fetch_template_metadata` (FTM)

Generated by `R/sandbox/fetch_template_metadata.R` from the **original**
`R/original/fetch_template_metadata.R` (read-only reference), as Phase-2 step 1.
They record the original's behaviour **faithfully, bugs included**. Refactor
divergences (below) are derived in the testthat step.

The original turns a directory of template WAVs into `df_templates` by
**reverse-parsing the filename** (a fixed-width validation regex + repeated
`strsplit("_")`), reading only the WAV header for `samples`/`sample.rate`.

## Faithful behaviours captured

- **FTM-01/05 — thin, filename-derived schema** (11 cols: `template_path/file/
  name/label`, `start/end`, `sample_rate`, `min/max_freq`, `wl`, `ovlp`).
  `template_start` is hardcoded `0`; `template_end = samples / sample.rate`
  (cut-relative, discarding source-relative bounds); **no** channel, pitch_shift,
  provenance, hashes, user/timestamp/comment.
- **FTM-02 — label = last `_` token.** Works here only because the species names
  contain spaces, not underscores; a label like `Substructure_C` would be
  truncated.
- **FTM-03 — fixed-width regex** `\d{3}\.\d{3}-\d{3}\.\d{3}s_\d{2}\.\d{3}-\d{2}\.\d{3}kHz`.
  The fixture cuts pass (3-digit seconds, 2-digit kHz); off-convention names are
  silently dropped with a warning (FTM-G3) or abort the call (FTM-G3n).
- **FTM-04 — `purrr::safely` drops unreadable files** silently (no unreadable
  file in these cases; documented for the testthat divergence).

## Refactor divergences (asserted in testthat, NOT in the golden)

- **FTM-101/102:** read the canonical `template_*` schema from the DuckDB
  manifest written by ERC; filename parsing kept only as a **migration** path
  (`migrate_templates_to_manifest`), width-agnostic.
- **FTM-02:** carry `template_label` verbatim from the manifest (no truncation).
- **FTM-05/06:** full canonical schema (channel, pitch_shift, provenance,
  `template_sha256`, source-relative bounds, user/timestamp/comment) + documented
  `@return`.
- **FTM-04:** collect unreadable files into a structured warning/log (FSM-204
  pattern), not a silent drop.
- **FTM-104:** resolve `reference_metadata` rows on demand from `soundscapes`
  metadata, verifying `origin_soundscape_sha256`.
