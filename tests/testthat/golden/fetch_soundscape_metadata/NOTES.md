# Golden notes — `fetch_soundscape_metadata`

Goldens generated by `R/sandbox/fetch_soundscape_metadata.R` from the
**original** `R/original/fetch_soundscape_metadata.R` (read-only reference), as Phase-2
step 1. They record the original's behaviour **faithfully, bugs included**.
The refactor's intentional divergences (listed below) are derived in the
testthat step (step 3) instead of compared verbatim — mirroring the
`fast_spectro` approach.

Run: `Rscript R/sandbox/fetch_soundscape_metadata.R`

## Artifacts per case

- `<case>.rds` / `<case>_metadata.csv` — output data frame, rows sorted by
  `soundscape_path` (canonical, filesystem-independent).
- `<case>_raworder.txt` — paths in the order the original returned them
  (documents FSM-15 non-determinism).
- `<case>_messages.txt` — verbatim `message()`/`warning()` output.
- `cache_reprocess_bug_error.txt` — the original's error condition (G6).
- `cache_missing_log_missinglog.csv` — the missing-recordings log the original
  wrote (G5), timestamp dropped from the filename.
- `summary.csv` — one row per case (counts, flags).

## Original schema captured (6 columns)

`soundscape_path`, `soundscape_file`, `soundscape_duration`,
`soundscape_sample_rate`, `soundscape_bitrate`, `soundscape_layout`.

> Note: `soundscape_bitrate` is the original's misnamed bit-depth column
> (FSM-13). The expanded canonical schema (FSM-211) is **not** part of any
> golden — the original never produced it; new-feature behaviour is validated
> with fresh tests, not golden comparison.

## Intentional divergences the refactor WILL introduce

The testthat step must **derive/assert these**, not `expect_equal` against the
golden verbatim:

1. **FSM-13** — column `soundscape_bitrate` → `soundscape_bitdepth`. Golden has
   the old name; test maps it.
2. **FSM-15** — refactor sorts results explicitly. Compare against the canonical
   (sorted) golden; `*_raworder.txt` documents the original's unsorted return.
3. **FSM-18** — short-duration signal moves from `message("Warning: …")` to a
   real `warning()`. Golden has it under `## messages`; test expects a warning.
4. **FSM-02 / FSM-14 / FSM-204 / FSM-214** — per-file read failures move from
   scattered `message("Error reading file…")` (G2, silently dropped) to an
   aggregated `warning()` + a structured, separately-inspectable error log
   (CSV sibling, or a `metadata_errors` table when the DuckDB backend lands).
   Test asserts: failed files are reported, not silently dropped.
5. **FSM-03** — G6 must stop crashing: cache + `skip_processed=FALSE` becomes
   "reprocess everything". Test asserts no error + full reprocess.
6. **FSM-07 / FSM-201** — `.wav` regex anchored + non-audio (`.txt`) excluded by
   an explicit guard. Golden already shows `CONFIG.TXT`/`*_Summary.txt` excluded
   on this corpus; test adds adversarial names (`foo_wav`, `notes.txt`, `.WAV`).
7. **FSM-211 / FSM-209 etc.** — new columns and the DuckDB backend are
   additive; not represented in these goldens (validated by new tests).
