Generated by `R/sandbox/fetch_score_peaks.R`, which sources the faithful
baselines `R/original/fetch_score_peaks.R` **and** its per-pair dependency
`R/original/fetch_score_peaks_i.R`. Each case writes `<label>.rds` (the batch
detection frame, or `NULL` on error) and `<label>.txt` (class/nrow/ncol/names +
captured messages/warnings). `MANIFEST.csv` enumerates all cases.

## Fixtures

- **SYNTH** — multi-row scores tibbles assembled from `make_score_row()` to pin

## Intentional divergences (refactor will CHANGE these — assert as derived)

The refactor applies the FSPB + FSP decisions; testthat asserts the new
behaviour against these goldens, not byte-equality:

- **FSPB-08 (shared routine, option A)** — `fetch_score_peaks` and the
  orchestrator both call one `.detect_peaks_batch()` emitting the **canonical
  24-col** `_schema_detections.R` (adds `detection_id`, `template_id`,
  `score_method`), so the batch output gains those columns vs the legacy 21 here.
- **FSPB-10 (filter decoupling, option C)** — capture becomes a **pure** step;
  filtering moves to a composable `filter_detections(detec, min_score=,
  min_quant=, top_n=, scope=)` over the canonical table, default `scope="pair"`
  (legacy default, reproduces `real_batch_*` filter rows), with `scope="grid"`
  opt-in (new). The captured `real_batch_min_score/min_quant/top_n3` goldens are
  the `scope="pair"` reference.
- **FSPB-05 (empty rbind)** — assembly via `purrr::list_rbind` over the canonical
  zero-row schema, so `synth_mixed_empty` keeps the schema for the empty pair and
  `synth_all_empty` returns a **typed 24-col zero-row** frame (not 0×0).
- **FSPB-02 (1-row floor)** — a single-row scores tibble is **accepted**, so
  `err_single_row` becomes a valid 1-pair run (no error) after the refactor.
- **FSPB-01 (parallel backend)** — the Windows-only / leaking `makePSOCKcluster`
  is replaced (cross-platform backend or sequential); behaviour on these
  single-thread goldens is unchanged.
- **FSPB-04 (persistence)** — CSV/RDS deprecated in favour of dedicated
  cross-compatible (DuckDB) functions; `output_file=.csv` may be retained as a
  legacy convenience or removed (documented). `err_rds_output`/`real_batch_csv`
  flag the legacy path.
- **FSPB-06 (return type)** — returns a **tibble**, not a base `data.frame`.
- **FSPB-07 (assembly/pbapply)** — `split`+`do.call(rbind)` replaced by
  `seq_len`+`list_rbind`; `pbapply` dependency re-evaluated.
- **FSPB-09 (empty message)** — the message reports the **detection count**;
  empty batch returns the typed schema.

Note: the absolute path inside `real_batch_csv`'s export message is
machine-specific — assert only its prefix (`Detections have been exported to`).
