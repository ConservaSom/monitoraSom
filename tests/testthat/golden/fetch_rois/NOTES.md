# Goldens — `fetch_rois` (FR)

Generated by `R/sandbox/fetch_rois.R` from the **original**
`R/original/fetch_rois.R` (read-only reference), as Phase-2 step 1. They record
the original's behaviour **faithfully, bugs included**. The refactor's intentional
divergences (below) are derived in the testthat step (step 3), not compared
verbatim — mirroring the `fast_spectro` / `fetch_soundscape_metadata` approach.

The original reads **legacy CSV** ROI tables (`fs::dir_ls(pattern="_roi_.*\\.csv$",
recurse=TRUE)`), coerces to a hand-maintained 19-column schema, and returns the
`rbind` of all tables.

## Faithful bugs captured (do not "fix" the golden)

- **FR-02 — phantom NA rows.** The dead `valid_entries <- !vapply(df_rois,
  is.null, ...)` operates on **columns** (length = ncol = 19). When the unified
  frame has **fewer rows than columns** (FR-G3: 2 real rows), `df_rois[valid_entries, ]`
  indexes rows with a length-19 all-`TRUE` logical → R **extends** the frame to
  19 rows, padding rows 3–19 with `NA`. Hence FR-G3 returns 19 rows (2 real + 17
  phantom). With more rows than columns (FR-G1/G2) the logical merely recycles
  all-`TRUE`, so the bug is invisible there.
- **FR-03 — silent NA coercion.** `as.numeric`/`as.integer` over character turns
  `"not_a_number"` and `""` into `NA` with no count/warning (visible in FR-G3,
  `n_na_roi_start`).
- **FR-05 — `recursive` ignored.** `fs::dir_ls(recurse = TRUE)` is hardcoded;
  the documented `recursive = FALSE` default has no effect.

## Refactor divergences (asserted in testthat, NOT in the golden)

- **FR-101/102:** read from the DuckDB ROI store (the `fixture_legacy` CSVs become
  the *migration* input); output the canonical 18-col `.roi_schema_spec()` —
  **drops** `roi_path`/`roi_file`, **adds** `roi_channel`.
- **FR-02:** remove the broken `valid_entries` block → FR-G3 should yield the 2
  real rows, no phantom NA rows.
- **FR-03:** report values that failed to parse (count + first offending file).
- **FR-05:** honour `recursive`.
- **FR-06:** normalize stored `soundscape_path` to forward slashes (cross-platform).
- **FR-103:** optional `origin_`-prefixed provenance columns when soundscape
  metadata is supplied.
